1. The Engineering Challenge: Why Naive LLM Workouts Fail

Large Language Models are probabilistic token generators, not deterministic calculators. When asked to plan hypertrophy workouts or progressive overload progressions, naive single-stage LLMs routinely make dangerous arithmetic errors: hallucinating unrealistic volume jumps (+80kg bench presses), prescribing mutually conflicting intensity zones, or forgetting recovery intervals across training cycles.

PulseFit AI solves this with a two-stage decoupled architecture: physical ground truth (tonnage, set volumes, fatigue indexes) is calculated deterministically in Python before any LLM prompt is constructed.

Flutter Client & Local-First Ingestion

Built with Flutter (Web & Mobile) using CanvasKit hardware acceleration. Workout logging saves instantly to HTML5 localStorage, guaranteeing sub-millisecond perceived latency even with flaky gym Wi-Fi.

  • Optimistic UI updates with offline-first persistence
  • Compiles via shared_preferences_web to browser localStorage
  • Async background sync to Supabase PostgreSQL via anonymous JWTs
  • Structured telemetry: reps, weight (kg), RPE, rest times

// lib/features/workout/services/workout_storage.dart
Future<void> saveCompletedSession(WorkoutSession session) async {
  // 1. Instant local persistence (0ms UI latency)
  await _localPrefs.setString(
    'last_session', jsonEncode(session.toJson())
  );

  // 2. Fire-and-forget cloud sync
  unawaited(_supabaseService.syncSession(session)
    .catchError((e) => _markPendingSync(session.id)));
}
